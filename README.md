# Toolbox

一个中文网页工具箱，把热量换算、计数器、商品比价和 Boss 计时放在同一页。用原生 HTML、CSS 和 JavaScript 编写，无需安装依赖或构建，计算与数据保存都在浏览器中完成。

## 四个工具

| 工具 | 用法 |
| --- | --- |
| 热量换算 | 输入千焦（kJ）或千卡（kcal），另一栏自动换算，结果四舍五入为整数。 |
| 计数器 | 点击加减或重置，也支持键盘操作。计数自动保存，同一站点的多个标签页会同步。 |
| 商品比价 | 按品类创建对比组，填写商品重量、件数、套数和总价，突出每 100g 单价，标出组内最划算的商品。 |
| Boss 计时 | 显示巢穴首领、世界首领的下次刷新时间和倒计时，临近刷新时高亮提醒。 |

比价时，件数指一套中有几件，套数指买了几套。比如每件 100 g、每套 3 件、买 2 套，共花 24 元，总重量就是 600 g，单价为 0.04 元/g，也就是每 100 g 花 4 元。不同规格的同类商品放进同一组即可比较。

Boss 计时按代码中预设的基准时间和周期推算，目前巢穴首领每 45 分钟一轮，世界首领每 3 小时 30 分钟一轮。它不读取游戏服务器状态；游戏日程调整后，需要更新预设。

## 本地使用

安装 Python 3 后，在项目目录运行：

```bash
python3 -m http.server 8000
```

浏览器打开 [本地工具箱](http://127.0.0.1:8000/)。关闭终端中的服务后，再次运行同一条命令即可继续使用。

也可以将 `index.html`、`styles.css`、`app.js` 和 `favicon.png` 放到静态网站托管服务上，无需后端。

### 键盘操作

切换到计数器后，按 `+` 或 `↑` 加一，按 `-` 或 `↓` 减一，按 `R` 重置。焦点不在输入框、按钮或顶部标签上时，也可以按空格加一。

顶部工具标签支持方向键切换，`Home` 和 `End` 跳到首尾。`Ctrl`、`⌘`、`Alt` 组合键仍交给浏览器处理。

## 数据保存在哪里

计数、比价记录和上次选择的工具保存在当前站点的浏览器本地存储（`localStorage`）中，不会上传到服务器。刷新页面后可继续使用已保存的数据；未提交的表单草稿不会跨刷新保存。

换浏览器、设备或访问地址，看到的是各自独立的数据。清除站点数据也会清除这些记录，目前没有导入、导出或云端备份功能。

多个标签页同时使用时，支持 Web Locks 的浏览器会依次处理写入；不支持时，检测到其他活跃标签页会提示先关闭。保存失败会显示提示，比价编辑失败后会保留草稿，方便重试。

## 开发与验证

页面结构在 [index.html](index.html)，样式在 [styles.css](styles.css)，四项工具的逻辑在 [app.js](app.js)。Boss 日程由 `app.js` 中的 `WORLD` 和 `NORMAL` 配置维护。

测试使用 Node.js 内置测试运行器，CI 使用 Node.js 22。在项目目录运行：

```bash
node --check app.js
node --test tests/*.test.js
```

[tests/app.test.js](tests/app.test.js) 检查换算、输入校验、计时边界等基础逻辑；[tests/runtime.test.js](tests/runtime.test.js) 覆盖跨标签计数、表单草稿恢复、保存失败回滚和编辑冲突。运行时测试使用 DOM 与存储替身；[浏览器测试](tests/browser/ui.test.cjs) 则在真实 Chromium 中检查编辑、焦点、错误反馈、跨标签同步和响应式布局。

运行浏览器测试前，需要安装开发依赖和 Chromium，网页本身仍无需构建：

```bash
npm ci
npx playwright install chromium
npm run test:browser
```

浏览器测试覆盖 320、375、640、768 和 1440px 宽度。失败截图保存在 `test-results/`。如需使用已安装的 Chrome，可通过 `CHROME_EXECUTABLE_PATH` 指定可执行文件路径。

推送到 `main` 或提交拉取请求时，[GitHub Actions](.github/workflows/ci.yml) 会自动运行单元、浏览器和部署资源三组测试，并保留浏览器测试的失败截图。

部署资源检查使用本地 Wrangler，不需要 Cloudflare 登录，也不会发布网站：

```bash
npm run test:deploy
```

它会验证部署预检、网站文件内容，以及依赖、配置和测试文件的 404 响应。部署由 `wrangler.jsonc` 配置，`.assetsignore` 仅允许四个网站文件；新增图片、脚本等公开资源时，需要同步更新白名单和部署测试。
